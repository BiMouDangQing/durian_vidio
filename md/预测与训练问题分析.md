# 榴莲成熟度模型：预测与训练问题分析及改进建议

> 日期：2026-08-27
> 涉及脚本：`train_linear_0809.py`（训练）、`predict.py`（预测）
> 模型：`lgbm_0824_model.pkl`（LGBMRegressor，huber 回归）
> 数据：`data_0824\duizhi`（87 样本，训练用）、`data_0827`（52 样本）、`data_all`（148 样本，21~168）

---

## 一、总体结论

| 项目 | 现状 | 结论 |
|------|------|------|
| 训练批次（data_0824）样本级准确率 | 87/87 = **100%** | 模型过拟合训练集 |
| 新批次（data_0827）样本级准确率 | 33/52 = **63.5%** | 跨批次泛化严重失败 |
| data_all 总体样本级准确率 | 128/148 = **86.5%** | 被新批次拉低 |
| 最差类别 | 类别 2（中熟）recall 仅 **69%** | 类别 2 是主要矛盾 |

**核心结论**：当前问题不是"阈值没调好"，而是**模型在训练批次上过拟合，对新批次存在严重的域偏移（domain shift）**，且**类别 2（中熟）天然最难分**。调阈值无效（详见 2.3）。

## 二、预测存在的问题

### 2.1 批次域偏移（最核心）

按样本 ID 拆分 data_all（148 样本）后：

| 批次 | 样本范围 | 样本数 | 准确率 |
|------|----------|--------|--------|
| data_0824（训练批次） | 21~107 | 87 | **100%** |
| 新增 | 108~116 | 9 | 88.9% |
| data_0827（新批次） | 117~168 | 52 | **63.5%** ⚠️ |

各类别样本级分数均值随批次**非线性漂移**：

| 类别 | data_0824 | data_0827 | 漂移量 |
|------|-----------|-----------|--------|
| 1 | 1.02 | 1.30 | -0.28 |
| 2 | 2.00 | **1.34** | **-0.66** |
| 3 | 2.98 | 2.54 | -0.44 |

**依据**：类别 2 的漂移量最大（-0.66），直接导致大批类别 2 被低估为类别 1。

### 2.2 类别 2（中熟）几乎不可分

样本级混淆矩阵（148 样本）：

| 真实\预测 | 预1 | 预2 | 预3 | recall |
|-----------|-----|-----|-----|--------|
| 真1（54） | 54 | 0 | 0 | 100% |
| 真2（48） | **15** | 33 | 0 | **69%** ⚠️ |
| 真3（46） | 1 | 4 | 41 | 89% |

- data_0827 中，**类别 1 分数均值 1.303 vs 类别 2 分数均值 1.340**，两者几乎完全重叠；
- data_0827 的 16 个类别 2 样本中 **15 个**分数 < 1.8 被误判为类别 1；
- 类别 2 是"清脆↔沉闷"的过渡态，特征边界天然模糊，受域偏移影响最大。

### 2.3 调阈值无法解决

对样本级分数做阈值网格扫描：

- 当前阈值 1.8/2.4 → 86.5%
- 最优阈值 1.75/2.10 → 仅 **87.2%**（+0.7%）

**依据**：类别 1 与类别 2 的分数分布重叠（不是整体平移），任何单一阈值都无法把重叠区切开。

## 三、训练脚本（train_linear_0809.py）存在的问题

### 3.1 【严重】评估阈值与真实标签、预测端都不一致

训练脚本中的类别映射是 **5 类**：

```python
def continuous_to_5class(x):
    if x < 1.4:   return 1
    elif x < 1.8: return 2
    elif x < 2.2: return 3
    elif x < 2.6: return 4
    else:         return 5
```

而训练目标 `y` 是 **1/2/3 三分类**。`evaluate_model` 里用同一个函数映射真实标签：

```python
true_cls = [continuous_to_5class(v) for v in y_test]   # y=1→1, y=2→3, y=3→5
```

**依据**：
- `y=1 → 1`、`y=2 → 3`（1.8≤2<2.2）、`y=3 → 5`（3≥2.6）；
- 导致训练 OOF 混淆矩阵的标签变成 `{1, 3, 5}`，与真实 `{1, 2, 3}` **错位**；
- 训练端用 5 类阈值（1.4/1.8/2.2/2.6），预测端用 3 类阈值（1.8/2.4），**训练评估与预测评估不可比**；
- 阈值 2.2/2.6 在训练数据里没有任何支撑（y 只有 1、2、3 三个值），属于无依据的"拍脑袋"。

### 3.2 【严重】label 加载脆弱，依赖隐式巧合

```python
def load_labels(max_files=120):
    df = pd.read_csv(LABEL_PATH, header=None)
    labels = df.iloc[:max_files, 0].values.astype(int)   # max_files=348 是"文件数"，不是样本数
    ...
```

```python
# main 中
y = np.repeat(load_labels(NUMBER), 20)   # 硬编码 20 = 4文件 × 5信号
```

**依据**：
- `NUMBER=87*4=348` 是文件数，却用来切 label 行数；之所以"碰巧正确"，是因为 label.csv 只有 87 行（<348），`iloc[:348]` 实际只返回 87 个标签；
- `np.repeat(labels, 20)` 硬编码了"每样本 4 文件 × 每文件 5 条信号"，一旦某文件不足 5 条非零信号，`X` 长度 < 1740 与 `y` 长度不匹配，直接错位或报错；
- `astype(int)` 遇到空行会报错——实测 `data_0827\label.csv` 第 53 行就是空行，用此写法读取会崩溃。

### 3.3 【中】死代码 + 缺失 import

`group_split_safe()` 使用了 `StratifiedShuffleSplit`，但：
- 文件头部只 `from sklearn.model_selection import GroupKFold`，**未导入 `StratifiedShuffleSplit`**；
- 该函数在 `evaluate_model` 里**从未被调用**（实际用的是 `GroupKFold`）。

**依据**：一旦被调用会直接 `NameError`；即使不报错，也是一段无用死代码，误导维护者以为训练用了分层划分。

### 3.4 【中】GroupKFold 不保证类别均衡

`evaluate_model` 用 `GroupKFold(n_splits=5)` 划分。

**依据**：
- `GroupKFold` 只保证"同组不跨折"，**不保证每折类别比例一致**；
- data_0824 共 87 样本中类别 2 只有 23 个，5 折下某些折可能几乎没有类别 2，导致评估波动大；
- 更合理用 `StratifiedGroupKFold`（按组 + 类别分层）。

### 3.5 【低】特征被重复提取

**依据**：`evaluate_model` 每个 fold 都对 `X_train`、`X_test` 各调用一次 `extract_features`，最后又对全量 `X` 调用一次，共重复提取 11 次；librosa 的 mel + mfcc 计算较慢，纯属浪费，应只提取一次并复用。

### 3.6 【中】模型复杂度相对数据量偏高

```python
LGBMRegressor(n_estimators=500, learning_rate=0.02,
              num_leaves=31, max_depth=6, ...)
```

**依据**：
- 有效独立样本只有 87 个（每瓜 20 条信号实为同一标签的重复敲击），`num_leaves=31 / max_depth=6` 对如此小样本偏复杂，易过拟合；
- 本项目历史经验（见仓库记忆）：小样本应使用**低复杂度强正则**（`num_leaves=4, max_depth=3, min_child_samples=40, reg_alpha=8, reg_lambda=15`）才稳定。

### 3.7 【严重】没有独立测试集，无法暴露跨批次问题

训练脚本只做 `GroupKFold` OOF 评估。

**依据**：
- OOF 只在同分布（data_0824）内交叉，结果高达 100%，给人"模型很好"的错觉；
- 实际放到 data_0827 只有 63.5%，**证明 OOF 严重高估了模型泛化能力**；
- 应留出独立测试集（尤其按批次留出，如 data_0824 训练 → data_0827 测试）。

### 3.8 【中】用回归处理有序分类，评估方式混乱

**依据**：
- 标签 1/2/3 是**有序类别**（1<2<3），不是等距连续值；
- 项目历史经验已明确：这类问题应优先用**有序分类（Ordinal Classification）**而非回归；
- 若坚持回归，训练端与预测端也必须统一用同一套 3 类阈值评估，避免 3.1 的错位问题。

## 四、训练修改意见（含依据）

### 建议 1：统一评估阈值为 3 类，或改用有序分类 【优先级：最高】

- **做法**：删除 5 类映射，训练端评估统一用 `score_to_class`（<1.8→1，<2.4→2，否则→3）；或直接改造成两个二分类器 `P(y≥2)`、`P(y≥3)` 的有序模型。
- **依据**：3.1 —— 当前 5 类阈值把 y=2→3、y=3→5，混淆矩阵标签错位，训练/预测两端不可比。

### 建议 2：显式映射 sample_id → label，去掉 `np.repeat` 【优先级：最高】

- **做法**：按 `sample_id` 读取 label，构建 `{sample_id: label}` 字典，逐信号/逐文件取对应标签；label 读取用 `pd.to_numeric(..., errors="coerce").dropna()` 跳过空行。
- **依据**：3.2 —— `np.repeat(labels, 20)` 硬编码依赖"4×5"巧合，且 `astype(int)` 遇空行崩溃（data_0827 已触发）。

### 建议 3：使用 StratifiedGroupKFold 【优先级：高】

- **做法**：`from sklearn.model_selection import StratifiedGroupKFold`，按 `groups=sample_id` 分层划分。
- **依据**：3.4 —— 类别 2 仅 23/87，`GroupKFold` 无法保证每折类别均衡，评估波动大。

### 建议 4：降低模型复杂度 + 强正则 【优先级：高】

- **做法**：小样本下改为 `num_leaves=4, max_depth=3, min_child_samples=40, reg_alpha=8, reg_lambda=15, max_bin=63`，`n_estimators` 用早停控制。
- **依据**：3.6 —— 87 个有效样本配 `num_leaves=31` 易过拟合；项目历史经验已验证低复杂度强正则更稳。

### 建议 5：特征只提取一次并复用 【优先级：中】

- **做法**：`main()` 里先 `X_feat = extract_features(X)` 一次，fold 内直接用索引切分。
- **依据**：3.5 —— 当前重复提取 11 次，纯性能浪费。

### 建议 6：增加独立测试集（按批次留出）【优先级：最高】

- **做法**：用 data_0824 训练、data_0827 作为独立 holdout 验证，报告 holdout 指标；最终模型再用 `data_all`（148 样本）重训。
- **依据**：3.7 —— OOF 100% vs 独立批次 63.5%，证明只有独立测试集才能暴露真实泛化能力。

### 建议 7：合并 data_all 重新训练 【优先级：高】

- **做法**：把 148 个样本全部纳入训练（StratifiedGroupKFold 交叉验证），让模型见到新批次分布。
- **依据**：2.1 —— 当前模型只在 data_0824 的 87 样本上训练，对 data_0827 泛化失败；增加训练覆盖是缓解域偏移最直接的手段。

### 建议 8：人工复核 data_0827 的类别 2 标签 【优先级：高】

- **做法**：复核 16 个类别 2 样本（sample_id：117、118、119、121、123、124、125、127、128、130、131、140、141、143、151），确认标注无误。
- **依据**：2.2 —— 这些样本分数中位数 1.256，甚至低于同批次类别 1（1.303），"类别 2 比类别 1 还像未熟"很反常，存在标注错误的可能。
- **修正**：经频谱质心全量统计（见第八章），未发现明确标注错误证据，低分更可能是域偏移；"复核"仍建议保留，但不再认定"标注错误"为主要嫌疑。

## 五、预测端修改意见

1. **按批次做分数校准/域适应**：用 Platt scaling 或 isotonic 校准连续分数；或按批次以"类别 1"为锚点对齐分数（类别 1 最稳定，漂移仅 0.28）。
   - 依据：2.1 各类别漂移量不一致，单一全局阈值失效。
2. **预测时给出分数置信区间**：当前置信度是 softmax 到类别中心距离，不代表"正确概率"，可改用分位数回归或集成方差估计不确定性。
3. **输出按批次分组指标**：预测结果中增加批次维度（如 `data_0824` / `data_0827`），便于监控不同批次的漂移。

## 九、8:2 训练/验证集划分策略（已整合进 train.py）

### 解决思路

原 `train.py` 用 5 折交叉验证（CV OOF）评估。CV 只在同分布内交叉，无法暴露跨批次问题，且评估后还需再全量训练一次才能得到最终模型。改为**按样本分层 8:2 划分**：80% 训练、20% 验证，一次训练即同时完成评估与产出模型，验证集指标即真实泛化水平。

### 实现细节

1. **分层划分**：`StratifiedShuffleSplit(test_size=0.2, random_state=42)` 按 sample_id 分层，保证训练/验证集类别比例一致（训练 43/38/37，验证 11/10/9）；
2. **按样本分组**：同一颗瓜的 20 条信号不跨训练/验证集（通过 sample_id 集合生成 mask）；
3. **信号级训练 + 样本级聚合评估**：LGBMRegressor（huber）在信号级训练（2366 条），按样本均值聚合到 148 样本评估；
4. **保留跨批次 holdout**：data_0824 → data_0827 作为跨批次泛化额外参考。

### 结果

| 集合 | 样本数 | 准确率 | 类别2 recall |
|------|--------|--------|-------------|
| 训练集 | 118 | **94.1%** | 82% |
| 验证集 | 30 | **80.0%** | **60%** ⚠️ |
| 独立批次(0824→0827) | 52 | 63.5% | 6% |

验证集 80.0% 与之前 CV OOF 79.7% 一致，说明评估诚实；类别 2 仍是唯一短板（4/10 被误判为生果）。

## 十、域适应实验：两个方法无效，根因是标签错误

### 实验 1：多批次联合训练（增量加入 data_0827 数据）

固定测试集为 data_0827 的 50%（26 样本，分层），训练集从"仅 data_0824"逐步加入 data_0827 剩余部分的 0%/25%/50%/100%：

| 加入 data_0827 样本数 | 测试准确率 |
|----------------------|-----------|
| 0 | 65.4% |
| 6 | 65.4% |
| 13 | 65.4% |
| 26 | 65.4% |

**结论**：加入最多 26 个 data_0827 样本，测试准确率不变——**多批次联合训练（少量目标批次数据）无效**。

### 实验 2：分数校准（Isotonic Regression）

训练=仅 data_0824，测试=data_0827 的 75%：

| 方法 | 测试准确率 |
|------|-----------|
| 不校准 | 66.7% |
| isotonic 校准（25% 校准集） | 64.1%（更差） |
| 直接加入训练（25% 数据） | 66.7%（不变） |

**结论**：isotonic 校准反而更差（校准集太小导致过拟合），直接加入训练也无效果——**分数校准无效**。

### 根因定位：data_0827 类别 2 标签大量错误

两个方法都无效，进一步用"批次自身交叉验证"对比：

| 批次 | 自身 5 折 CV 准确率 | 类别2 recall |
|------|--------------------|-------------|
| data_0824（87 样本） | 86.2% | **81%** |
| data_0827（52 样本） | 65.4% | **12.5%** ⚠️ |

## 十三、train.py 简化：移除独立批次测试，改为 7:3 训练/测试划分（2026-08-31）

### 13.1 修改原因

1. **独立批次测试逻辑已不合用**：原 `run_holdout()` 用固定 sample_id 边界（`BATCH_TRAIN_MAX=107`、`BATCH_TEST_MIN=117`）切分，注释写的是 data_0824（21~107）→ data_0827（117~168）；但当前数据已换成 **data_0830**（sample_id 21~327，连续无空缺）。在 data_0830 上运行时，测试批实际变成 **117~327（211 样本）**，远大于训练批 21~107（87 样本），与注释语义严重不符。
2. **需求变化**：不再需要跨批次独立测试，改用常规的训练/测试划分即可，评估逻辑更简单、结果更稳定。

### 13.2 修改内容

| 项 | 修改前 | 修改后 |
|----|--------|--------|
| 划分方式 | 8:2 训练/验证集（`TEST_SIZE=0.2`） | **7:3 训练/测试集（`TEST_SIZE=0.3`）** |
| 独立批次测试 | `run_holdout()` + 固定批次边界 | **已删除** |
| 批次边界常量 | `BATCH_TRAIN_MAX=107` / `BATCH_TEST_MIN=117` | **已删除** |
| 术语 | "验证集" | 统一为"测试集" |
| 文件 docstring | "8:2 训练/验证集版" | "7:3 训练/测试集版" |

删除的代码块：

```python
def run_holdout(X_feat, y, groups):
    train_mask = groups <= BATCH_TRAIN_MAX
    test_mask = groups >= BATCH_TEST_MIN
    model = build_model()
    model.fit(X_feat[train_mask], y[train_mask])
    pred = model.predict(X_feat[test_mask])
    ...
```

### 13.3 验证结果（data_0830，7:3 分层划分）

- 训练集 **214** 样本 / 测试集 **93** 样本；

## 十四、特征帧数修复 + 正则收紧（2026-08-31）

### 14.1 修改原因

1. **帧数陷阱（主要问题）**：`n_fft=512, hop=256` 下，600 点信号只能切出 **1 帧**，导致 MEL std（64 维）、MEL max（64 维）、MFCC std（20 维）共 **148 维特征退化**（std 恒 0、max 等于 mean），238 维里约 62% 没有信息量。
2. **过拟合**：训练集与测试集差距 12.8 个百分点（90.2% vs 77.4%），模型复杂度偏高、正则偏弱。

### 14.2 修改内容

| 项 | 修改前 | 修改后 |
|----|--------|--------|
| STFT 窗长 `n_fft` | 512（1 帧） | **256（6 帧）** |
| 帧移 `hop_length` | 256 | **64** |
| `n_estimators` | 250 | **150** |
| `num_leaves` | 16 | **8** |
| `min_child_samples` | 20 | **40**（≈2 样本） |
| `reg_lambda` | 5.0 | **10.0** |

## 十五、类别 2 优化诊断：样本加权无效、阈值校准不稳定（2026-08-31）

### 15.1 诊断背景

帧数修复后，类别 2（中间果）仍是唯一瓶颈（测试 recall 47%、precision 0.35）。针对"类别 2 声学重叠"尝试两个方向：样本加权、单独校准阈值。

### 15.2 实验 1：类别 2 样本加权（固定阈值 1.7/2.2）

| 类别2 权重 | 测试准确率 | 类别2 recall |
|-----------|-----------|-------------|
| 1.0（基线） | 77.4% | 46.7% |
| 2.0 | **78.5%** | 46.7% |
| 3.0 | 74.2% | 46.7% |
| 4.0 | 73.1% | 53.3% |
| 5.0 | 72.0% | 53.3% |

**结论**：样本加权基本无效——w2=2.0 最多 +1 个点，w2≥3 总体准确率反而下降（类别 2 recall 略升但以牺牲整体为代价）。

### 15.3 实验 2：阈值校准（三种方法）

| 方法 | 得到的最优阈值 | 评估准确率 | 可靠性 |
|------|---------------|-----------|--------|
| 当前固定阈值 | 1.7 / 2.2 | 77.4%（7:3 测试） | — |
| 训练集校准 | 1.75 / 2.4 | **75.3%**（变差） | 无泄漏但分数偏移 |
| 测试集扫描 | 1.75 / 2.15 | 81.7% | **有泄漏，不可用** |
| 5 折 CV 中位数 | 1.95 / 2.25 | 82.4%（OOF） | 无泄漏，但各折阈值波动大 |

5 折 CV 各折最优 t1 波动 **1.65~2.0**、t2 波动 **2.0~2.35**。

**关键发现**：
- 用训练集校准阈值，测试集反而降到 75.3%——证明训练/测试的分数分布存在系统偏移（与历史结论一致）；
- 测试集扫描的 81.7% 是用测试集选阈值，属数据泄漏，不能用于部署；
- 5 折 CV 虽给出 82.4% 的无泄漏估计，但各折最优阈值高度不稳定（t1 波动 0.35），说明"最优阈值"本身在小样本下不可靠。

### 15.4 最终结论

1. **样本加权无效**，**阈值校准在小样本下不可靠**（训练集校准变差、测试集扫描泄漏、CV 阈值不稳定）；
2. 根因：**"回归 + 固定阈值"这一后处理方案在小样本下对数据划分高度敏感**，阈值无法稳定确定；
3. **建议**：放弃"回归 + 阈值"，改用**直接三分类（LGBMClassifier）**或**有序分类（Ordinal Classification）**，从根上消除阈值依赖——这与项目早期"标签是离散有序类别，应用有序分类而非回归"的结论一致；
4. 因此本次诊断**未改动阈值**（保留 1.7/2.2），仅记录结论供后续改造参考。

## 十六、无监督聚类可行性实验（2026-08-31）

### 16.1 实验目的

验证能否用**无监督学习（无标签自我聚类）**替代有监督分级。用 data_0830（307 样本，238 维声学特征）做样本级聚类，对比真实标签。

### 16.2 实验结果

| 算法 | ARI | NMI | 纯度 |
|------|-----|-----|------|
| KMeans(3) | 0.243 | 0.236 | 0.704 |
| GMM(3) | 0.240 | 0.224 | 0.700 |
| 层次聚类(3) | 0.257 | 0.248 | 0.678 |

- ARI（调整兰德指数）≈ 0.24，远低于 1（完全一致）与 0.5（较强一致），仅"弱相关"；
- 纯度 0.70 看似不低，但标签最大类占比 48.5%，聚类只是"比瞎猜好一点"。

### 16.3 失效原因：中间果在声学空间没有独立簇

KMeans(3) 簇-标签交叉表：

```
       簇0  簇1  簇2
真实1   61   79    9
真实2   14   23   13   ← 中间果被彻底拆散
真实3   28    4   76
```

- 簇 2 基本是熟果（76/98），相对干净；
- 但**中间果（50 个）被拆成 14/23/13 散落到三个簇**，没有任何一个簇以中间果为主——无监督聚类连"中间果是一个等级"都发现不了。

**根因**：声学空间里最显著的分化维度是"清脆→沉闷"主轴（生果→熟果），中间果恰好骑在过渡带上，与两端声学重叠；"声音相似"≠"成熟度相同"（还混入敲击力度、个体差异等无关因素）。

### 16.4 结论

1. **无监督聚类无法替代有监督分级**（ARI 0.24），与有监督模型"类别 2 recall 仅 40~47%"的诊断互相印证；
2. 无监督仍有三个**辅助用途**：
   - **离群检测**：IsolationForest 找出落不进任何簇的样本（31/307），这些多为采集异常或标签可疑，值得人工复核——Top 异常样本中混有多个类别 2，恰是"声学边界模糊"样本；
   - **半监督/主动学习**：聚类后每簇只人工标注代表点，减少标注量；
   - **数据探索可视化**：PCA/t-SNE 观察天然簇结构。

- 输出：`results/unsupervised/<时间戳>/` 下的 `tsne_clusters.png`、`outlier_samples.csv`（按异常分数升序，越靠前越可疑）。

## 十七、无监督探索扩展 + 异常数据筛选脚本（2026-08-31）

| KMeans | 3 | 0.212 | 0.234 | 0.157 | 70.0 | 1.841 |

| GMM | 3 | 0.205 | 0.227 | 0.158 | 70.0 | 1.855 |

| OPTICS | 1 | 0.000 | 0.051 | — | — | — |

三个关键发现：

2. **密度聚类在高维失效**：DBSCAN 把 297/307 聚成一个巨簇 + 6 个噪声，OPTICS 更甚（298/307 全判噪声）——238 维特征空间里距离度量失效（维度灾难），密度聚类完全不可用；
3. **簇结构本身很弱**：Silhouette 全部仅 0.15 左右，从无监督角度再次印证"声学空间没有清晰的成熟度簇"。

### 17.2 改造成异常数据筛选脚本

把探索脚本改造成实用筛选器，核心是三路投票 + 综合异常分数：

| 组件 | 说明 |
|------|------|
| IsolationForest | 树隔离度（连续分数） |
| LOF | 局部密度（连续分数） |
| DBSCAN 噪声 | 密度聚类噪声点 |
| 综合分数 | 0.4×IF + 0.4×LOF + 0.2×DBSCAN噪声（归一化 0~1，越大越异常） |
| 三级判定 | ≥2 票建议剔除 / 1 票建议复核 / 0 票正常 |

> 修正：初版四路投票含 OPTICS，但其高维失效（298/307 噪声）导致"正常"仅剩 4 个，已去掉，改三路投票。

筛选结果（data_all，307 样本）：

| 等级 | 数量 |
|------|------|
| 建议剔除（≥2 票） | 21 |
| 建议复核（1 票） | 21 |
| 正常保留 | 265 |

- 剔除前标签分布 `{1:91, 2:108, 3:108}` → 剔除后 `{1:77, 2:100, 3:88}`；
- 满 3 票的样本：`71、28、316、30、97`；中间果 `318、251` 也在剔除清单（声学边界最模糊样本）。

### 17.3 结论

1. 6 种聚类算法都无法可靠自我分级（最好谱聚类 ARI 0.288），再次确认无监督不可替代有监督；
2. 密度聚类（DBSCAN/OPTICS）在 238 维特征空间因维度灾难失效，不适合本数据；
3. 筛选脚本的实用价值：三路投票 + 综合分数能稳定锁定"采集异常/标签可疑"样本，输出 `remove_list.csv`（建议剔除）与 `clean_list.csv`（保留）可直接用于数据清洗。
